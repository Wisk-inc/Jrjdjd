Running CorX3.8, and how the chat works.

The chat talks to CorX3.8 on your own server. This page has the server code to copy, the four steps to connect it, and how Agent mode’s terminal, files and uploads work.

CorX3.8-27B is too big to run in a browser, so it runs on a GPU you provide — a notebook like molab or Colab, or a rented GPU box. The code below turns that GPU into an OpenAI-compatible API and opens a public URL. You paste that URL into the chat’s settings, and the browser talks to your model directly.

Step 1 · The server

Copy this and run it on a GPU.

Paste the whole thing into one notebook cell and run it. First run installs dependencies and loads the model (1–2 minutes), then it prints a public URL.

"""
================================================================
 CorX3.8-27B — API SERVER for the CorX Labs site
 CorX Labs / Nathan

 Serves the model as an OpenAI-compatible endpoint your website
 can call. transformers backend (vLLM crashed on Qwen3.8 GDN).
================================================================
"""

import os
os.environ["CUDA_VISIBLE_DEVICES"] = "0"
os.environ["PYTORCH_CUDA_ALLOC_CONF"] = "expandable_segments:True"

import subprocess
import sys
import json
import time
import threading
import queue
import uuid
import urllib.request
import gc
import asyncio

# ---------------- SETTINGS ----------------
MODEL_REPO   = "Sigmandndnns/CorX3.8-27B"
HF_TOKEN     = ""
PORT         = 8000
MAX_NEW_TOKENS_CAP = 32000

# Precision. "auto" measures the GPU and picks: full bf16 when the card can
# hold the whole 27B (~54GB) — an RTX PRO 6000 Blackwell, H100, A100 80GB —
# and 4-bit on smaller cards so it still fits in VRAM instead of spilling to
# CPU. Force it with "bf16" or "4bit".
PRECISION = "auto"

# auth
NO_AUTH      = True                     # True = keyless (your "unrestricted")
API_KEY      = "corx-key"               # used only if NO_AUTH = False

# concurrency
QUEUE_TIMEOUT = 120                     # seconds a request waits for the GPU
STREAM_TIMEOUT = 300                    # seconds to wait for a token before
                                        # giving up. Must cover prefill of the
                                        # whole prompt on a 27B model — too low
                                        # and you get "[Generation Error]".
# ------------------------------------------

print("Installing deps (first run only)...")
_deps = ["fastapi", "uvicorn[standard]", "transformers", "accelerate"]
if PRECISION != "bf16":          # may still be needed if auto picks 4-bit
    _deps.append("bitsandbytes")
subprocess.run([sys.executable, "-m", "pip", "install", "-q", "-U", *_deps],
               check=False)

import torch
from transformers import (AutoTokenizer, AutoModelForCausalLM,
                          TextIteratorStreamer)

if HF_TOKEN:
    os.environ["HF_TOKEN"] = HF_TOKEN

print(f"GPUs visible: {torch.cuda.device_count()}")
if torch.cuda.device_count() == 0:
    raise RuntimeError("No GPU attached to this molab session.")

# ---------------- PICK PRECISION FROM THE ACTUAL CARD ----------------
_props = [torch.cuda.get_device_properties(i) for i in range(torch.cuda.device_count())]
TOTAL_VRAM_GB = sum(p.total_memory for p in _props) / 1e9
_cap = f"{_props[0].major}.{_props[0].minor}"
print(f"GPU: {_props[0].name} — {TOTAL_VRAM_GB:.0f} GB total VRAM, compute {_cap}, torch {torch.__version__}")

# A new architecture (Blackwell is sm_120) needs a PyTorch built with kernels
# for it. On an older wheel every CUDA op dies with a bewildering "no kernel
# image is available" — so say plainly what to do before loading 54GB.
try:
    _supported = torch.cuda.get_arch_list()
    if _supported and f"sm_{_props[0].major}{_props[0].minor}" not in _supported:
        print(f"[warn] This torch was built for {_supported} — nothing for sm_{_props[0].major}{_props[0].minor}.")
        print("       If loading fails with 'no kernel image is available', install a matching build:")
        print("       pip install -U --index-url https://download.pytorch.org/whl/cu128 torch")
except Exception:
    pass

# 27B bf16 weights are ~54GB; leave headroom for the KV cache and activations.
_BF16_NEEDS_GB = 62
if PRECISION == "auto":
    LOAD_IN_4BIT = TOTAL_VRAM_GB < _BF16_NEEDS_GB
    print(f"[precision] auto → {'4-bit' if LOAD_IN_4BIT else 'full bf16'} "
          f"({TOTAL_VRAM_GB:.0f} GB {'<' if LOAD_IN_4BIT else '>='} {_BF16_NEEDS_GB} GB)")
else:
    LOAD_IN_4BIT = (PRECISION == "4bit")
    print(f"[precision] forced → {'4-bit' if LOAD_IN_4BIT else 'full bf16'}")
    if not LOAD_IN_4BIT and TOTAL_VRAM_GB < _BF16_NEEDS_GB:
        print(f"[warn] Only {TOTAL_VRAM_GB:.0f} GB of VRAM — bf16 will spill to CPU and be slow.")

# ---------------- LOAD MODEL ----------------
tok_kwargs = {"trust_remote_code": True}
if HF_TOKEN:
    tok_kwargs["token"] = HF_TOKEN

print(f"Loading CorX3.8-27B in {'4-bit' if LOAD_IN_4BIT else 'bf16'} (1-3 min)...")
tok = AutoTokenizer.from_pretrained(MODEL_REPO, **tok_kwargs)
if tok.pad_token is None:
    tok.pad_token = tok.eos_token

load_kwargs = dict(trust_remote_code=True, low_cpu_mem_usage=True)
# transformers renamed torch_dtype -> dtype; pick whichever this version takes
# so the load is clean on both.
import inspect as _inspect
_load_params = _inspect.signature(AutoModelForCausalLM.from_pretrained).parameters
load_kwargs["dtype" if "dtype" in _load_params else "torch_dtype"] = torch.bfloat16
if HF_TOKEN:
    load_kwargs["token"] = HF_TOKEN

# SDPA is PyTorch's built-in fused attention — a solid speedup over the
# eager path on any modern card, and it needs no extra package.
try:
    load_kwargs["attn_implementation"] = "sdpa"
except Exception:
    pass

if LOAD_IN_4BIT:
    # Small card: quantise so the whole model still sits in VRAM. Spilling to
    # CPU is what makes the first token take minutes and trip the timeout.
    from transformers import BitsAndBytesConfig
    load_kwargs["device_map"] = "auto"
    load_kwargs["quantization_config"] = BitsAndBytesConfig(
        load_in_4bit=True,
        bnb_4bit_compute_dtype=torch.bfloat16,
        bnb_4bit_quant_type="nf4",
        bnb_4bit_use_double_quant=True)
elif torch.cuda.device_count() == 1:
    # Enough VRAM and one card: put the whole model on GPU 0 explicitly.
    # Pinning it beats device_map="auto", which keeps the offload machinery
    # in play and can still decide to park something on the CPU.
    load_kwargs["device_map"] = {"": 0}
else:
    load_kwargs["device_map"] = "auto"   # shard across the cards

model = AutoModelForCausalLM.from_pretrained(MODEL_REPO, **load_kwargs)
model.eval()
# NOTE: do not set generation_config.cache_implementation = "static" here.
# A static cache sends generate() down the torch.compile / _inductor path,
# which throws inside the worker thread ("Detected that you are using FX
# tracing...") — no tokens are ever produced and the request just hangs.
# The default dynamic cache is correct for this server.
print(f"Model ready. VRAM in use: {torch.cuda.memory_allocated()/1e9:.1f} GB "
      f"of {TOTAL_VRAM_GB:.0f} GB")

# Confirm nothing landed off-GPU — this is the usual root cause of a first
# token that never arrives.
try:
    _dev = set(str(d) for d in model.hf_device_map.values())
    if any(d in ("cpu", "disk") for d in _dev):
        print("[warn] Part of the model is on CPU/disk — generation will be SLOW.")
        print("       Set PRECISION = \"4bit\" so it fits entirely in VRAM.")
    else:
        print(f"[ok] Whole model resident on GPU ({sorted(_dev)}).")
except Exception:
    pass

# ---------------- GENERATION (single GPU, queued) ----------------
_job_lock = threading.Lock()

# Worker wrapper to ensure gradients are off in the background thread.
# If generation dies, end the streamer straight away and hand the reason
# back — otherwise the reader sits waiting for a token that will never come
# and the request only fails much later, on a timeout, with no explanation.
def _generate_thread_worker(kwargs, streamer=None, err_box=None):
    with torch.inference_mode():
        try:
            model.generate(**kwargs)
        except Exception as e:
            import traceback
            traceback.print_exc()
            print(f"\n[Generation Error in thread] {type(e).__name__}: {e}")
            if err_box is not None:
                err_box.append(f"{type(e).__name__}: {e}")
            if streamer is not None:
                try:
                    streamer.end()        # unblock the reader immediately
                except Exception:
                    pass

def _generate(messages, max_new_tokens, temperature, streamer=None, err_box=None):
    prompt = tok.apply_chat_template(messages, tokenize=False,
                                     add_generation_prompt=True)
    inputs = tok(prompt, return_tensors="pt").to(model.device)
    kwargs = dict(**inputs,
                  max_new_tokens=min(int(max_new_tokens), MAX_NEW_TOKENS_CAP),
                  temperature=max(float(temperature), 0.01),
                  top_p=0.9, do_sample=float(temperature) > 0,
                  repetition_penalty=1.05,
                  pad_token_id=tok.pad_token_id or tok.eos_token_id)

    if streamer is not None:
        kwargs["streamer"] = streamer
        # Must target our safe wrapper instead of model.generate directly
        threading.Thread(target=_generate_thread_worker,
                         args=(kwargs, streamer, err_box),
                         daemon=True).start()
        return None

    with torch.inference_mode():
        out = model.generate(**kwargs)
    return tok.decode(out[0][inputs["input_ids"].shape[1]:],
                      skip_special_tokens=True)

# ---------------- OPENAI-COMPATIBLE API + CORS ----------------
from fastapi import FastAPI, Request, HTTPException
from fastapi.responses import StreamingResponse, JSONResponse
from fastapi.middleware.cors import CORSMiddleware
import uvicorn

app = FastAPI(title="CorX3.8 API")

app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

def check_auth(request: Request):
    if NO_AUTH:
        return
    if request.headers.get("authorization", "") != f"Bearer {API_KEY}":
        raise HTTPException(status_code=401, detail="bad api key")

@app.get("/health")
async def health():
    return {"status": "ok", "model": "corx3.8",
            "vram_gb": round(torch.cuda.memory_allocated()/1e9, 1),
            "busy": _job_lock.locked()}

@app.get("/v1/models")
async def list_models(request: Request):
    check_auth(request)
    return {"object": "list",
            "data": [{"id": "corx3.8", "object": "model",
                      "owned_by": "corx-labs"}]}

@app.post("/v1/chat/completions")
async def chat_completions(request: Request):
    check_auth(request)
    body = await request.json()
    messages = body.get("messages", [])
    if not messages:
        raise HTTPException(status_code=400, detail="messages required")
    max_new = body.get("max_tokens", 2048)
    temperature = body.get("temperature", 0.7)
    stream = bool(body.get("stream", False))
    cid = f"chatcmpl-{uuid.uuid4().hex[:12]}"

    got = _job_lock.acquire(timeout=QUEUE_TIMEOUT)
    if not got:
        raise HTTPException(status_code=503, detail="model busy, retry shortly")

    if not stream:
        try:
            text = _generate(messages, max_new, temperature)
            return JSONResponse({
                "id": cid, "object": "chat.completion", "model": "corx3.8",
                "choices": [{"index": 0, "finish_reason": "stop",
                             "message": {"role": "assistant", "content": text}}],
            })
        except Exception as e:
            import traceback; traceback.print_exc()
            return JSONResponse(status_code=500,
                content={"error": {"message": f"{type(e).__name__}: {e}",
                                    "type": "generation_error"}})
        finally:
            # Bulletproof release & GC
            try: _job_lock.release()
            except RuntimeError: pass
            torch.cuda.empty_cache()
            gc.collect()

    async def event_stream():
        try:
            # This is the wait for the NEXT token, and the first one only
            # arrives after the whole prompt is prefilled. A 27B model with a
            # long system prompt (and any CPU offload) can take well over a
            # minute to get there, so a short timeout here shows up in the
            # chat as "[Generation Error]" even though nothing actually failed.
            streamer = TextIteratorStreamer(
                tok, skip_prompt=True, skip_special_tokens=True, timeout=STREAM_TIMEOUT)
            err_box = []          # filled by the worker if generate() throws
            _generate(messages, max_new, temperature, streamer=streamer,
                      err_box=err_box)

            _DONE = object() # Sentinel value to prevent StopIteration Exception
            sent_any = False

            while True:
                try:
                    # Pass _DONE as the default value to next() so it doesn't throw an error to asyncio
                    chunk = await asyncio.to_thread(next, streamer, _DONE)

                    if chunk is _DONE:
                        break # Stream finished successfully

                    data = {"id": cid, "object": "chat.completion.chunk",
                            "model": "corx3.8",
                            "choices": [{"index": 0, "delta": {"content": chunk},
                                         "finish_reason": None}]}
                    sent_any = True
                    yield f"data: {json.dumps(data)}\n\n"

                except queue.Empty:
                    print(f"[api] No token for {STREAM_TIMEOUT}s — giving up. "
                          f"Raise STREAM_TIMEOUT, shorten the prompt, or load in 4-bit.")
                    err = {"id": cid, "object": "chat.completion.chunk",
                           "model": "corx3.8",
                           "choices": [{"index": 0, "delta": {"content":
                                        f"\n[No token produced within {STREAM_TIMEOUT}s. "
                                        f"The model is likely still prefilling — raise STREAM_TIMEOUT "
                                        f"in the server, or load the model in 4-bit so it fits the GPU.]"},
                                        "finish_reason": "error"}]}
                    yield f"data: {json.dumps(err)}\n\n"
                    break

            # generate() died before producing anything: say what actually
            # went wrong instead of returning an empty, silent reply.
            if err_box and not sent_any:
                err = {"id": cid, "object": "chat.completion.chunk",
                       "model": "corx3.8",
                       "choices": [{"index": 0, "delta": {"content":
                                    f"\n[Generation failed on the server: {err_box[0]}]"},
                                    "finish_reason": "error"}]}
                yield f"data: {json.dumps(err)}\n\n"

            done = {"id": cid, "object": "chat.completion.chunk",
                    "model": "corx3.8",
                    "choices": [{"index": 0, "delta": {},
                                 "finish_reason": "stop"}]}
            yield f"data: {json.dumps(done)}\n\n"
            yield "data: [DONE]\n\n"
        finally:
            # Bulletproof release & GC for streaming
            try: _job_lock.release()
            except RuntimeError: pass
            torch.cuda.empty_cache()
            gc.collect()

    return StreamingResponse(event_stream(), media_type="text/event-stream")

# ---------------- START SERVER (background thread) ----------------
_server_ready = threading.Event()

def serve():
    config = uvicorn.Config(app, host="0.0.0.0", port=PORT, log_level="warning")
    server = uvicorn.Server(config)
    _server_ready.set()
    server.run()

threading.Thread(target=serve, daemon=True).start()
_server_ready.wait(timeout=10)
time.sleep(2)

try:
    urllib.request.urlopen(f"http://127.0.0.1:{PORT}/health", timeout=5)
    print(f"[api] local server healthy on :{PORT}")
except Exception as e:
    print(f"[api] WARNING: local server not responding ({type(e).__name__})")

# ---------------- CLOUDFLARE QUICK TUNNEL (zero account) ----------------
import re
import platform

def get_cloudflared():
    path = os.path.abspath("./cloudflared")
    if os.path.exists(path):
        return path
    arch = platform.machine().lower()
    if arch in ("x86_64", "amd64"):
        url = ("https://github.com/cloudflare/cloudflared/releases/latest/"
               "download/cloudflared-linux-amd64")
    elif "aarch64" in arch or "arm64" in arch:
        url = ("https://github.com/cloudflare/cloudflared/releases/latest/"
               "download/cloudflared-linux-arm64")
    else:
        url = ("https://github.com/cloudflare/cloudflared/releases/latest/"
               "download/cloudflared-linux-amd64")
    print(f"[tunnel] downloading cloudflared ({arch})...")
    urllib.request.urlretrieve(url, path)
    os.chmod(path, 0o755)
    return path

def start_cloudflare_tunnel(port, timeout=40):
    binary = get_cloudflared()
    proc = subprocess.Popen(
        [binary, "tunnel", "--no-autoupdate", "--url", f"http://localhost:{port}"],
        stdout=subprocess.PIPE, stderr=subprocess.STDOUT, text=True, bufsize=1)
    url = None
    url_re = re.compile(r"https://[-a-z0-9]+\.trycloudflare\.com")
    start = time.time()
    while time.time() - start < timeout:
        line = proc.stdout.readline()
        if not line:
            if proc.poll() is not None:
                break
            continue
        m = url_re.search(line)
        if m:
            url = m.group(0)
            break
    def _drain():
        for _ in proc.stdout:
            pass
    threading.Thread(target=_drain, daemon=True).start()
    return url, proc

PUBLIC_URL = None
tunnel_proc = None
for attempt in range(2):
    try:
        PUBLIC_URL, tunnel_proc = start_cloudflare_tunnel(PORT)
        if PUBLIC_URL:
            print(f"[tunnel] live: {PUBLIC_URL}")
            break
        time.sleep(3)
    except Exception as e:
        print(f"[tunnel] attempt {attempt+1} failed: {str(e)[:80]}")
        time.sleep(3)

print("\n" + "=" * 66)
if PUBLIC_URL:
    print(" CorX3.8-27B API IS LIVE")
    print("=" * 66)
    print(f" Public URL : {PUBLIC_URL}/v1")
    print(f" Health     : {PUBLIC_URL}/health")
    print(f" Auth       : {'NONE (open)' if NO_AUTH else 'Bearer ' + API_KEY}")
    print(f" Model      : corx3.8")
else:
    print(" TUNNEL FAILED — API is live LOCALLY")
print("=" * 66)
print("Paste the Public URL (without /v1) into the CorX chat Settings.")

_KEEP_ALIVE = tunnel_proc

# ---------------- BLOCK FOREVER so the cell never completes ----------------
while True:
    try:
        time.sleep(15)
        if tunnel_proc is not None and tunnel_proc.poll() is not None:
            print("[tunnel] cloudflared exited — restarting...")
            new_url, tunnel_proc = start_cloudflare_tunnel(PORT)
            if new_url:
                PUBLIC_URL = new_url
                print(f"[tunnel] back up: {PUBLIC_URL}/v1")
            _KEEP_ALIVE = tunnel_proc
    except KeyboardInterrupt:
        print("stopped by user.")
        break
    except Exception as _e:
        print(f"[keepalive] {type(_e).__name__}: {_e}")
        time.sleep(5)

Which GPU? CorX3.8 needs roughly 24 GB of GPU memory in 4-bit, or about 54 GB in full bf16. You don't have to choose: PRECISION = "auto" measures the card at start-up and loads full bf16 when there is room for it (RTX PRO 6000 Blackwell, H100, A100 80GB), dropping to 4-bit only on smaller cards. Force it either way with PRECISION = "bf16" or "4bit".

On a single card that fits the model, it is pinned to GPU 0 rather than left to device_map="auto" — that keeps the offload machinery out of the picture entirely. The cell prints which precision it chose and confirms the whole model is resident on the GPU; if anything lands on CPU or disk it says so, because that is what makes the first token take minutes.

On a brand-new card (Blackwell is sm_120) PyTorch must have kernels built for it, or every CUDA call fails with “no kernel image is available”. The script checks and, if your build is too old, prints the install line: pip install -U --index-url https://download.pytorch.org/whl/cu128 torch.

Step 2 · Connect

Paste the URL into the chat.

  1. Wait for “API IS LIVE”

    When the cell prints CorX3.8-27B API IS LIVE, it shows a Public URL like https://something.trycloudflare.com/v1. Copy it without the /v1 — the chat adds that for you.

  2. Open the chat and its settings

    Go to the chat and click the model name at the top (or the gear icon) to open Model & connection. With CorX3.8 selected, paste the URL into Server address and press Save.

  3. Watch the status dot

    The dot by the title turns green · Online when it connects (it checks the server’s /health). Red means it can’t reach the server — check the cell is still running and the URL is current.

  4. Leave the cell running

    The server lives as long as that cell runs. The code blocks on purpose so the notebook doesn’t tear it down, and restarts the tunnel if it drops.

Or bring your own model. The same Model & connection panel has a provider picker: pick OpenRouter, Claude, DeepSeek or OpenAI, paste that provider’s API key (stored in your browser only, sent only to that provider), and choose a model. The whole agent — search, terminal, files, plan — then runs on that model instead. Two of these call the provider straight from the browser and just work: OpenRouter (one key, most models) and Claude. DeepSeek and OpenAI block direct browser calls, so they’re marked proxy and will hit a CORS wall unless you front them yourself — use OpenRouter to reach GPT or DeepSeek models from the browser.

Step 3 · Agent tools

It runs code, files and a plan on its own.

There is no toggle to switch on — every conversation can use tools: run Python, make and edit files, install packages and plan a task. CorX3.8 decides for itself when a tool would help and calls it without asking permission first. The tools run in a real Python sandbox inside your browser tab — not on the model server — so you can watch every command in the Terminal panel and nothing touches your computer outside the tab.

What it can do

  • Run Python and see the real output in the Terminal
  • Create, edit, save and delete files in the Files panel
  • Install Python packages with micropip
  • Publish a plan and tick off each step as it works
  • Take a zip or file you upload and work on it, with Python's own zipfile module
  • Search the web and fetch a page's real content, on its own initiative
  • Recall relevant bits of your other saved chats
  • Pull real pictures into the chat with find_image (Wikimedia Commons, credited)
  • Read its own traceback when code fails and try to fix it on the next round

The panel, search & uploads

Open the work panel with the panel button by the title. It has three tabs: Terminal (commands as they run, and you can type Python yourself), Files (everything the sandbox holds, shared across every chat in this tab — click one to edit, save or delete), and Plan (the live checklist).

A real web search runs through /api/search (DuckDuckGo, no key) with a sliding row of site logos while it searches, then a Searched the web dropdown you can open to see every link and snippet. /api/fetch reads a page's actual content, including any code shown on it.

The upload button in the composer stages files — including .zip archives — into the sandbox at /work. Ask the agent to unzip, read or transform them.

Honest note on tools. The model server is a plain chat endpoint with no built-in tool-calling, so every system prompt teaches CorX3.8 a small text format for asking to run a tool. Whether it uses tools well depends on the model following that format — it is a Patois-focused fine-tune, not a dedicated tool-use model, so expect it to be better at conversation than at long autonomous chains. If it ever ignores a tool it should have used, ask it directly and it will call it.

Step 4 · Effort

Low to Max — a real dial, not a label.

The Effort selector in the composer changes actual request parameters: how many tokens the model is allowed per reply, how many tool-call rounds the agent gets before it must stop, how many search results it pulls back, and how hard the system prompt tells it to think, weigh alternatives, verify its own steps and search when unsure. Higher effort genuinely takes longer and spends more tokens — that trade is the point, for a task that is actually hard.

Extra and Max also add a second pass: after producing code or a solution, the model is told to stop and deliberately review its own work for bugs or missed cases — as if critiquing someone else's pull request — before presenting it as done, and to say so plainly and correct itself if it realises mid-answer that something it already said was wrong.

Effort is set per conversation and remembered when you come back to that chat.

Conversations & profile

Saved in this browser, nowhere else.

Conversations

Every chat lives in the sidebar — switch between them, delete one, or start a New chat. Messages, the plan, the agent toggle and the effort level are all saved per conversation and restored exactly as you left them after a refresh, a closed tab, or days away. The Python sandbox itself is not per-conversation — it is one real Python process for the whole tab, so its files are shared across every chat you have open.

Interrupted runs resume themselves

If you refresh mid-task, the chat notices on reload and starts picking the run back up automatically after a few seconds — Dismiss if you'd rather not. Because the Python sandbox resets on every reload, the agent is told plainly that it did, and to check what actually exists with list_files before assuming anything survived.

Profile

Click your name at the bottom of the sidebar to set a name and a photo. Both are saved locally and used to label your messages — never sent anywhere, and not part of what the model itself receives.

Cross-chat memory

With Memory on in your profile, the agent can call search_memory to grep your other saved conversations for relevant context — a real keyword search over what is in this browser, not a hidden server-side record.

Honest limits

What this set-up is, and isn’t.

  • The URL is ephemeral. A Cloudflare quick tunnel gives a new address every restart, and the notebook recycles. When the chat goes Offline, re-run the cell and paste the new URL. A permanent public chat needs a persistent host and a fixed domain.
  • One GPU, one job at a time. The server queues requests and returns a clear “busy” rather than faking concurrency. Fine for a demo; not for real traffic.
  • Open by default. Keyless means anyone with the URL can use your GPU while it is up. Set NO_AUTH = False and an API_KEY to lock it down, then put the key in settings.
  • The model can be wrong. CorX3.8 is an open research model. Don’t rely on it for facts without checking.

Optional · Heretic mode

The uncensored build, at full precision.

Same chat, same tools, a different set of weights. Heretic runs Qwen3.8-27B-Heretic-Abliterated — the same base CorX3.8 was built on, with the refusal direction removed. Run this cell instead of the one above and paste the URL it prints into the same box.

Read this first. Abliterated means the part of the network that produces refusals has been edited out. It will answer almost anything asked of it, including things it should not, and it is no more accurate than the normal build — removing the refusals does not add knowledge. There is no filter left except you.

The tunnel URL is public and keyless by default. Anyone holding it can use this model on your GPU, under your connection. If you run Heretic, set NO_AUTH = False and an API_KEY, and do not paste the URL anywhere. Everything it generates is your responsibility, not the model’s.

def gpu_info():
    """Name, VRAM in GB, compute capability — from nvidia-smi, so this script
    needs no torch."""
    try:
        out = subprocess.check_output(
            ["nvidia-smi", "--query-gpu=name,memory.total,compute_cap",
             "--format=csv,noheader,nounits"], text=True).strip().splitlines()
        name, mem, cap = [x.strip() for x in out[0].split(",")]
        return name, float(mem) / 1024.0, cap
    except Exception as e:
        raise RuntimeError(
            f"No NVIDIA GPU visible ({type(e).__name__}). Heretic needs a CUDA "
            "card — a 27B on CPU is minutes per reply, which is what the "
            "front-end reports as a timeout."
        ) from e

def _works(path):
    if not (os.path.isfile(path) and os.access(path, os.X_OK)):
        return False
    try:
        env = dict(os.environ, LD_LIBRARY_PATH=os.path.dirname(path))
        subprocess.run([path, "--version"], stdout=subprocess.DEVNULL,
                       stderr=subprocess.DEVNULL, timeout=60, env=env)
        return True
    except Exception:
        return False


def _release(tag=None):
    url = ("https://api.github.com/repos/ggml-org/llama.cpp/releases/latest"
           if tag is None else
           f"https://api.github.com/repos/ggml-org/llama.cpp/releases/tags/{tag}")
    req = urllib.request.Request(url, headers={"User-Agent": "corx-heretic"})
    try:
        with urllib.request.urlopen(req, timeout=20) as r:
            return json.load(r)
    except Exception as e:
        print(f"[build] could not read release info ({type(e).__name__})")
        return {}


def try_prebuilt_cuda():
    """llama.cpp publishes CUDA builds for Linux x64. When one is there it saves
    the 5-15 minute compile. Not always published, so this may find nothing —
    that is not an error, we just build instead."""
    machine = platform.machine().lower()
    if machine not in ("x86_64", "amd64"):
        print(f"[build] no prebuilt CUDA for {machine}; building from source.")
        return None
    for tag in (None,):
        rel = _release(tag)
        for a in rel.get("assets", []):
            n = a["name"].lower()
            if ("ubuntu" in n or "linux" in n) and "cuda" in n \
                    and ("x64" in n or "amd64" in n) \
                    and (n.endswith(".tar.gz") or n.endswith(".zip")):
                print(f"[build] prebuilt CUDA asset: {a['name']}")
                try:
                    dl = os.path.join("/tmp", a["name"])
                    urllib.request.urlretrieve(a["browser_download_url"], dl)
                    ex = "/tmp/llama-cuda-extract"
                    shutil.rmtree(ex, ignore_errors=True)
                    os.makedirs(ex, exist_ok=True)
                    if dl.endswith(".zip"):
                        with zipfile.ZipFile(dl) as zf:
                            zf.extractall(ex)
                    else:
                        with tarfile.open(dl, "r:gz") as tf:
                            tf.extractall(ex)
                    found = glob.glob(os.path.join(ex, "**", "llama-server"),
                                      recursive=True)
                    if not found:
                        print("[build] archive had no llama-server; building instead.")
                        return None
                    src_dir = os.path.dirname(found[0])
                    os.makedirs(BIN_DIR, exist_ok=True)
                    # the shared ggml/cuda libs sit beside the binary — take them all
                    for f in os.listdir(src_dir):
                        s = os.path.join(src_dir, f)
                        if os.path.isfile(s):
                            shutil.copy2(s, os.path.join(BIN_DIR, f))
                    os.chmod(SERVER_BIN, 0o755)
                    if _works(SERVER_BIN):
                        print(f"[build] using prebuilt CUDA binary: {SERVER_BIN}")
                        return SERVER_BIN
                    print("[build] prebuilt binary would not run here; building instead.")
                    return None
                except Exception as e:
                    print(f"[build] prebuilt fetch failed ({type(e).__name__}: {e}); "
                          "building instead.")
                    return None
    print("[build] no prebuilt CUDA asset published; building from source.")
    return None


def build_from_source():
    print("[build] installing build deps...")
    sh("apt-get -qq update && apt-get -qq install -y build-essential cmake git ccache",
       check=False, stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL)
    if not os.path.isdir(LLAMA_SRC):
        print("[build] cloning llama.cpp...")
        sh(["git", "clone", "--depth", "1",
            "https://github.com/ggml-org/llama.cpp", LLAMA_SRC], check=True)

    # nvcc must know the card. Blackwell is sm_120 and needs CUDA 12.8+; on an
    # older toolkit this dies deep in a compile log nobody reads.
    try:
        nvcc = subprocess.check_output(["nvcc", "--version"], text=True)
        v = re.search(r"release (\d+)\.(\d+)", nvcc)
        if v:
            major, minor = int(v.group(1)), int(v.group(2))
            print(f"[build] CUDA toolkit {major}.{minor}")
            if int(CUDA_ARCH) >= 120 and (major, minor) < (12, 8):
                print(f"[warn] sm_{CUDA_ARCH} needs CUDA 12.8 or newer; this is "
                      f"{major}.{minor}. Expect the build to fail — use a runtime "
                      f"with a newer toolkit.")
    except Exception:
        print("[warn] nvcc not found — is the CUDA toolkit installed?")

    build = os.path.join(LLAMA_SRC, "build")
    print(f"[build] compiling for sm_{CUDA_ARCH} (5-15 min, cached afterwards)...")
    sh(["cmake", "-S", LLAMA_SRC, "-B", build, "-DGGML_CUDA=ON",
        f"-DCMAKE_CUDA_ARCHITECTURES={CUDA_ARCH}", "-DLLAMA_CURL=OFF",
        "-DCMAKE_BUILD_TYPE=Release"], check=True)
    sh(["cmake", "--build", build, "--config", "Release",
        "-j", str(os.cpu_count() or 4), "--target", "llama-server"], check=True)
    built = os.path.join(build, "bin", "llama-server")
    if not os.path.exists(built):
        raise RuntimeError("Build finished but llama-server is missing — see the log above.")
    os.makedirs(BIN_DIR, exist_ok=True)
    for f in os.listdir(os.path.dirname(built)):
        s = os.path.join(os.path.dirname(built), f)
        if os.path.isfile(s):
            shutil.copy2(s, os.path.join(BIN_DIR, f))
    os.chmod(SERVER_BIN, 0o755)
    print(f"[build] ok: {SERVER_BIN}")
    return SERVER_BIN

def gguf_variants(files):
    """One entry per variant, with split shards grouped together."""
    groups = {}
    for f in files:
        if not f.lower().endswith(".gguf"):
            continue
        base, folder = os.path.basename(f), os.path.dirname(f)
        m = _SPLIT_RE.match(base)
        stem = m.group("stem") if m else base[:-5]
        groups.setdefault((folder, stem), []).append(f)
    return {k: sorted(v) for k, v in groups.items()}


def choose_variant(variants):
    def tag_of(stem):
        low = stem.lower()
        for t in BEST_TO_WORST:
            if t in low:
                return t
        return None

    scored = []
    for (folder, stem), files in variants.items():
        t = tag_of(stem)
        if t is not None:
            scored.append((BEST_TO_WORST.index(t), t, stem, files))
    if not scored:
        (folder, stem), files = sorted(variants.items())[0]
        print(f"[model] no quant tag in any filename; using {stem}")
        return stem, files
    scored.sort()

    if PRECISION == "full":
        for rank, t, stem, files in scored:
            if t in ("f32", "bf16", "f16", "fp16"):
                if NEEDS_GB[t] > VRAM_GB:
                    print(f"[warn] {t.upper()} wants ~{NEEDS_GB[t]} GB and this card "
                          f"has {VRAM_GB:.0f} GB. It will spill to system RAM and be "
                          f"unusably slow. Set PRECISION = \"auto\" instead.")
                print(f"[model] full precision → {stem} ({t.upper()})")
                return stem, files
        print(f"[warn] no F16/BF16 in this repo; taking the largest: {scored[0][2]}")
        return scored[0][2], scored[0][3]

    if PRECISION == "auto":
        for rank, t, stem, files in scored:
            if NEEDS_GB[t] <= VRAM_GB:
                print(f"[model] auto → {stem} ({t.upper()}, ~{NEEDS_GB[t]} GB "
                      f"of {VRAM_GB:.0f} GB)")
                return stem, files
        print(f"[warn] nothing here fits {VRAM_GB:.0f} GB; using the smallest.")
        return scored[-1][2], scored[-1][3]

    want = PRECISION.lower()
    for rank, t, stem, files in scored:
        if want in stem.lower():
            print(f"[model] forced → {stem}")
            return stem, files
    raise RuntimeError(f'PRECISION = "{PRECISION}" matches nothing in {MODEL_REPO}. '
                       f"Available: {sorted({s[2] for s in scored})}")

# Watch the startup log for what device it actually chose. This is the check
# that was missing: "-ngl 999" is a request, not a guarantee, and when it is
# refused llama.cpp says so here and then runs on the CPU anyway.
DEVICE_INFO = {"device": None, "offloaded": None, "layers": None,
               "cpu_only": None, "software": False}
_LOG_TAIL = []


def _note_llama_line(line):
    """Read one startup line. Kept separate so the logic is testable.

    A software Vulkan device is sticky: llama.cpp still prints
    "offloaded 63/63 layers to GPU" when that GPU is llvmpipe, so a later
    happy-looking line must not clear the finding."""
    low = line.lower()
    m = re.search(r"offloaded\s+(\d+)\s*/\s*(\d+)\s+layers?\s+to\s+gpu", low)
    if m:
        DEVICE_INFO["offloaded"] = int(m.group(1))
        DEVICE_INFO["layers"] = int(m.group(2))
    m2 = re.search(r"using device (\S+)\s*\((.*?)\)", line, re.I)
    if m2 and not DEVICE_INFO["device"]:
        DEVICE_INFO["device"] = f"{m2.group(1)} ({m2.group(2)})"
    if "llvmpipe" in low or "lavapipe" in low or "swiftshader" in low:
        DEVICE_INFO["device"] = "SOFTWARE RASTERISER (CPU)"
        DEVICE_INFO["software"] = True
    DEVICE_INFO["cpu_only"] = bool(
        DEVICE_INFO["software"]
        or (DEVICE_INFO["offloaded"] is not None and DEVICE_INFO["offloaded"] == 0))


def _watch_llama():
    for line in llama_proc.stdout:
        _LOG_TAIL.append(line)
        del _LOG_TAIL[:-400]
        _note_llama_line(line)
        sys.stdout.write("[llama] " + line)


threading.Thread(target=_watch_llama, daemon=True).start()


def wait_for_llama(timeout):
    """llama-server answers /health with 503 while loading, 200 once it can
    generate."""
    start = time.time()
    while time.time() - start < timeout:
        if llama_proc.poll() is not None:
            raise RuntimeError(
                f"llama-server exited with code {llama_proc.returncode} before it "
                f"was ready. Last lines:\n" + "".join(_LOG_TAIL[-25:]))
        try:
            with urllib.request.urlopen(f"http://127.0.0.1:{LLAMA_PORT}/health",
                                        timeout=5) as r:
                if r.status == 200:
                    return True
        except Exception:
            pass
        time.sleep(3)
    return False

# ---------------- WARM-UP: measure it before trusting it ----------------
# The first request pays for prompt prefill and CUDA graph setup. Do that here
# so the chat's first message is not the thing that discovers it, and print the
# real rate so "is it fast enough" is answered by this cell.
def warmup():
    body = {"model": MODEL_ID, "max_tokens": 24, "stream": False,
            "messages": [{"role": "user", "content": "Say READY and nothing else."}]}
    req = urllib.request.Request(
        f"http://127.0.0.1:{LLAMA_PORT}/v1/chat/completions",
        data=json.dumps(body).encode(),
        headers={"content-type": "application/json"})
    t0 = time.time()
    with urllib.request.urlopen(req, timeout=300) as r:
        out = json.load(r)
    dt = time.time() - t0
    n = (out.get("usage") or {}).get("completion_tokens") or 24
    return dt, n / dt if dt > 0 else 0.0


print("[llama] warming up...")
try:
    WARM_S, TOK_S = warmup()
    print(f"[llama] warm-up took {WARM_S:.1f}s — about {TOK_S:.1f} tokens/sec")
    if TOK_S < 3:
        print("[warn] under 3 tok/s. That is CPU-class speed; replies will take "
              "minutes and the chat will look hung. Check the device line above.")
except Exception as e:
    WARM_S, TOK_S = 0.0, 0.0
    print(f"[warn] warm-up failed ({type(e).__name__}: {e}) — continuing anyway.")

@app.post("/v1/chat/completions")
async def chat_completions(request: Request):
    check_auth(request)
    body = await request.json()
    if not body.get("messages"):
        raise HTTPException(status_code=400, detail="messages required")
    body["model"] = MODEL_ID          # one model is loaded; this is what you get
    if body.get("max_tokens"):
        body["max_tokens"] = min(int(body["max_tokens"]), MAX_NEW_TOKENS_CAP)
    stream = bool(body.get("stream", False))

    _bump(1)
    if not stream:
        try:
            r = await _client.post(f"{LLAMA}/v1/chat/completions", json=body)
            return JSONResponse(status_code=r.status_code, content=r.json())
        except Exception as e:
            return JSONResponse(status_code=500, content={"error": {
                "message": f"{type(e).__name__}: {e}", "type": "generation_error"}})
        finally:
            _bump(-1)

    async def relay():
        try:
            async with _client.stream(
                    "POST", f"{LLAMA}/v1/chat/completions", json=body,
                    headers={"Accept": "text/event-stream",
                             "Accept-Encoding": "identity"}) as r:
                if r.status_code != 200:
                    detail = (await r.aread()).decode("utf-8", "replace")[:400]
                    yield _err_chunk(f"\n[llama.cpp returned {r.status_code}: {detail}]")
                    yield b"data: [DONE]\n\n"
                    return
                # llama.cpp already emits exactly the chunk shape the chat parses,
                # [DONE] included, so pass the bytes straight through.
                async for chunk in r.aiter_bytes():
                    yield chunk
        except Exception as e:
            # Swallowing this was why a failure looked like a hang: the browser
            # got a 200 with an empty body and waited for tokens that never came.
            tail = "".join(_LOG_TAIL[-6:]).strip().replace("\n", " ")[:300]
            yield _err_chunk(f"\n[Generation failed on the server: "
                             f"{type(e).__name__}: {e}. Last server log: {tail}]")
            yield b"data: [DONE]\n\n"
        finally:
            _bump(-1)

    return StreamingResponse(relay(), media_type="text/event-stream")

def get_cloudflared():
    path = os.path.abspath("./cloudflared")
    if os.path.exists(path):
        return path

    suffix = "arm64" if ("aarch64" in arch or "arm64" in arch) else "amd64"

    print(f"[tunnel] downloading cloudflared ({arch})...")
    urllib.request.urlretrieve(url, path)
    os.chmod(path, 0o755)
    return path


def start_cloudflare_tunnel(port, timeout=40):
    binary = get_cloudflared()
    proc = subprocess.Popen(
        [binary, "tunnel", "--no-autoupdate", "--url", f"http://localhost:{port}"],
        stdout=subprocess.PIPE, stderr=subprocess.STDOUT, text=True, bufsize=1)
    url_re = re.compile(r"https://[-a-z0-9]+\.trycloudflare\.com")
    url, start = None, time.time()
    while time.time() - start < timeout:
        line = proc.stdout.readline()
        if not line:
            if proc.poll() is not None:
                break
            continue
        m = url_re.search(line)
        if m:
            url = m.group(0)
            break

    def _drain():
        for _ in proc.stdout:
            pass
    threading.Thread(target=_drain, daemon=True).start()
    return url, proc

Why this one is built differently. That repo ships GGUF, not safetensors, so the backend here is llama.cpp rather than transformers. The cell compiles llama-server with CUDA for your exact card the first time (5–15 minutes, then cached), asks the Hub which files the repo actually contains, downloads the right one, and puts a thin FastAPI layer in front so the site sees the identical /health and /v1/chat/completions contract as the normal server. Nothing in the chat needs to change.

Full precision means the F16 file. A GGUF repo ships one file per quantisation, so PRECISION = "full" pulls the F16/BF16 weights — roughly 54 GB, nothing quantised, every layer on the GPU. That wants about 64 GB of VRAM once the 32k KV cache is in there. On a smaller card use PRECISION = "auto" and it takes the largest file that fits, or name a quant directly with "q8_0" or "q4_k_m". Large files come as shards; the script fetches all of them and hands llama.cpp the first.

When it prints HERETIC API IS LIVE, paste the Public URL into settings the same way, then set the model field to corx3.8-heretic. Sandbox, search, files, GitHub and personalities all work exactly as they do on the normal build.

If the chat says it “did not respond within 25s”. That is almost never the address. The usual cause is the model running on the CPU while everything still looks fine: a Vulkan build on a notebook box picks up lavapipe, a software rasteriser, so -ngl 999 reports “63/63 layers offloaded to GPU” and then generates at a few seconds per token. A 27B is unusable there, and the front end can only report the silence.

This cell will not let that happen quietly. It is CUDA-first, it reads the startup log for the device it actually got, and it refuses to hand you a URL if the model landed on the CPU. Before printing the address it runs a warm-up generation and tells you the measured tokens/sec — so you know it is fast enough without finding out in the chat. Set REQUIRE_GPU = False if you want it to serve anyway.

The chat helps from its side too: when your own server misses the window it asks /health — which answers instantly even while generation crawls — and tells you which problem you have, a dead tunnel URL or a model on the wrong device, quoting the device and tok/s it reported.
