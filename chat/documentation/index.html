1. What this is

CorX Chat is an orchestrator, not a model. It does not run its own weights. It sits between you and the top available OpenAI models, decides which one should answer, breaks long jobs into steps, and gives the model a set of tools it does not normally have: a real sandboxed terminal, web search, file and archive editing, image generation, and memory that survives between sessions.

Model access comes from your own ChatGPT account, connected through the free Sign in with ChatGPT browser extension. There is no CorX account and no shared key.

The interface follows the conventions people already know from chat apps — a conversation list on the left, the thread in the middle, a composer at the bottom, a work panel on the right — because familiarity is worth more than novelty here. The visual language, type and colour are CorX Labs' own.

2. Connecting

CorX Chat is a hosted web app, and a hosted web app must never hold your ChatGPT credentials. That is the whole reason for the extension: it performs the OAuth handoff in a context the website cannot read, and stores the resulting credentials encrypted in your browser's own storage.

  1. The page checks for the extension

    On load, /chat/ looks for the Sign in with ChatGPT extension — first for an injected marker, then with a postMessage handshake that resolves as "not installed" after a short timeout. Nothing is sent anywhere during this check.

  2. If it is missing, you are offered the right link

    The install button points at the Chrome Web Store or Firefox Add-ons depending on your browser. Install it, reload, and the first step turns green.

  3. If it is already installed, you skip straight to Continue

    Detection is automatic — you never have to tell the page whether you have it. Pressing Continue asks the extension to authorise.

  4. You authorise with your ChatGPT account

    The extension runs the OAuth flow and keeps the credentials encrypted locally. When it completes, the workspace unlocks: models, terminal, search and canvas all become available.

Each person uses their own account. Credentials are never pooled, shared or redistributed. Which models you can reach, and what rate limits apply, are set by your own ChatGPT plan — not by CorX Labs.

The detection contract lives in one place, so it can be adjusted if the extension changes what it exposes:

// assets/js/chat.js
CorxChat.config.extension = {
  globalKey:   '__signInWithChatGPT',  // window marker, if injected
  datasetFlag: 'siwcInstalled',        // <html data-siwc-installed="true">
  pingType:    'siwc:ping',            // postMessage handshake out
  pongType:    'siwc:pong',            // …and the reply we wait for
  timeoutMs:   900                     // no reply by then → treat as missing
};

3. Models

The model list is fetched live from the proxy's /v1/models endpoint rather than hardcoded, so the picker shows what your account can actually reach today instead of a list that goes stale. Switching models mid-conversation keeps the thread — you can start on a fast model and move to a reasoning model when a question turns out to be harder than it looked.

Only models exposed through the Codex-compatible endpoints are available, and that set changes over time and by plan. Image generation is reached through the same route via /v1/images/generations.

5. The sandbox

The terminal is real. A full CPython build runs in WebAssembly inside your browser tab. The agent drives it: it writes code, runs it, reads the actual traceback when it fails, and fixes it. Every command and its output appear in the terminal panel as they happen — and you can type into it yourself.

It can install packages with micropip, create and edit files under /work, and reach the internet: inside Python, import web then await web.get(url). Those requests go out through /api/fetch on this origin, which is what stops CORS from boxing the sandbox in.

Because it runs in your tab, it has no access to your computer — only to its own in-memory filesystem and whatever you upload. Closing the tab discards it.

The shell understands pip install, ls, cat, rm, python <file>, pwd and help. Anything else is executed as Python — which is the honest framing, because that is what this is. There is no git, no node, no apt.

The panel closes with the × in its header, or the toggle in the chat toolbar. It reopens by itself when the agent next runs something.

The point of showing it. An assistant that claims code works and one that shows you the passing output are different products. The terminal is there so you can check the second thing — and catch it doing something you did not intend.

6. Uploads

Attach anything. Images are sent to the model as multimodal content, so it reads what is actually in the screenshot or photo. Any other file is written into the sandbox at /work/<name> and the agent is told it is there, so it can open it, parse it, edit it and write a new version back out — which then appears in the canvas as a download.

That covers data files, code, archives and anything else Python can open. Files stay in your browser; they are never uploaded to a CorX server.

7. Canvas mode

Long answers bury code. Canvas mode collects everything the agent generates into the side panel instead: grouped by category — scripts, data, output, documents — and rendered in the code's own style rather than as flat text.

Each file can be opened, read properly and downloaded individually, or taken together as an archive. The conversation stays a conversation; the artefacts stay artefacts.

8. Agent mode and task planning

Given a long job, the agent writes its own plan before it starts, then works through the steps and shows the checklist updating as each one completes. This matters for tasks that would otherwise stall halfway through with "would you like me to continue?" — the plan is what lets it keep going.

Plans are visible and revisable. If the third step is wrong you can say so while the first two are still running, rather than waiting for a finished answer built on a bad assumption.

9. Reasoning and research

Answers that need more than a line open with the model's reasoning, collapsed into a thought process dropdown. It is asked to actually think in there — weigh an alternative, name the case that breaks its plan, say when it is unsure — rather than narrate. Open it when you want to know why; ignore it when you do not.

For anything that depends on current information, it can read the live page with fetch_url and tell you which source it used, instead of answering from memory. There is no ranked search index behind it yet, so give it a URL or expect it to reason about where to look.

10. Language and region

CorX Chat detects the language you write in and answers in that language, including mid-conversation switches. It also detects your country or region so that locally-dependent answers and research are relevant where you actually are.

Both are defaults, not rules. Ask it to answer in English regardless, or to stop using your region, and it will for the rest of the conversation.

11. Memory

Your conversation is saved in this browser and restored when you come back, so closing the tab mid-task does not lose the thread. The last 40 turns are kept.

It is stored locally — in localStorage under corx.chat.v1 — not on a CorX server. New chat clears it, and so does signing out. Clearing your browser's site data removes both the conversation and the stored credentials.

12. Privacy and credentials

The design rule is simple: CorX Labs never holds your ChatGPT credentials.

  • The extension performs the OAuth handoff; the website never sees the exchange.
  • Credentials are stored encrypted in your browser's own storage.
  • They are attached to individual requests from your side and used to call the proxy for that request only. They are not persisted server-side between requests.
  • There is no pooled or shared token. Every user's access is their own.

Anything you send — messages, attachments, files created in the sandbox — is processed to answer you, and your prompts go to your own ChatGPT account, so OpenAI's terms and data handling apply to that leg exactly as they would if you were using ChatGPT directly. Don't paste secrets you wouldn't paste into ChatGPT.

13. Limits

CorX Chat is an interface and an orchestrator built by a one-person lab. It is genuinely useful and it is not a hardened commercial product. Here is where it stops.

  • It depends on your ChatGPT plan. Model availability, quality and rate limits are your account's, not ours. If your plan can't reach a model, neither can this.
  • The extension is required. There is no way to use it without installing the sign-in extension, and it works only in browsers that extension supports.
  • The models still make mistakes. The terminal and the visible sources exist so you can check the work, not so you can skip checking it.
  • The sandbox is bounded. Sessions are isolated and not permanent; long-running or resource-heavy jobs can be cut short, and the sandbox has no access to your machine.
  • Deep research is a judgement, not a guarantee. Weighting sources by reliability is better than ignoring the question — it is not the same as being right.
  • Not for safety-critical use. Same rule as everything else CorX Labs publishes.

14. FAQ

Does CorX Labs see my credentials?

No. The extension performs the OAuth handoff and stores credentials encrypted in your browser. They are attached to individual requests from your side and are not persisted server-side. There is no pooled token.

Which models can I use?

Whichever your own ChatGPT plan can reach through the Codex-compatible endpoints. The picker is populated from /v1/models at runtime, so it reflects your account rather than a fixed list.

Is the terminal real?

Yes — a full CPython build running in WebAssembly in your tab. The agent writes code, runs it, reads the real traceback when it fails and fixes it; it installs packages, reads and writes files, and reaches the internet. Every command is visible, and you can type into it yourself. It has no access to your computer.

Where does my chat history live?

In this browser, under corx.chat.v1 in localStorage — never on a CorX server. The last 40 turns are restored when you return. New chat clears it, signing out clears it, and clearing site data removes it along with your stored credentials.

Can I plug in my own backend?

Yes. The interface never talks to a model directly — every turn goes through CorxChat.transport.send, which posts to CorxChat.config.endpoint. Replace that one function and the whole UI runs against your own orchestrator.
