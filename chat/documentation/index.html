1. What this is

CorX Chat is an orchestrator, not a model. It does not run its own weights. It sits between you and the top available OpenAI models, decides which one should answer, breaks long jobs into steps, and gives the model a set of tools it does not normally have: a real sandboxed terminal, web search, file and archive editing, image generation, and memory that survives between sessions.

Model access comes from your own ChatGPT account, connected through the free Sign in with ChatGPT browser extension. There is no CorX account and no shared key.

The interface follows the conventions people already know from chat apps — a conversation list on the left, the thread in the middle, a composer at the bottom, a work panel on the right — because familiarity is worth more than novelty here. The visual language, type and colour are CorX Labs' own.

2. Connecting

CorX Chat is a hosted web app, and a hosted web app must never hold your ChatGPT credentials. That is the whole reason for the extension: it performs the OAuth handoff in a context the website cannot read, and stores the resulting credentials encrypted in your browser's own storage.

  1. The page looks for a session you already have

    On load, /chat/ calls completeLogin() — which picks up a sign-in you are returning from — and then getSession(). If a session is there, the workspace opens straight away and you are not asked anything. Nothing leaves your browser during this check.

  2. Otherwise you press Connect

    Connect with ChatGPT calls startLogin(). The library talks to the Sign in with ChatGPT extension itself — there is no detection heuristic on our side to get wrong.

  3. If the extension is missing, you get the right link

    startLogin() returns needs-extension together with the install URL for your browser, and the page points Get the extension at it. Install, press Connect again, and it continues.

  4. You authorise with your ChatGPT account

    The extension runs the OAuth flow and keeps the credentials encrypted locally. When it completes, the workspace unlocks: models, terminal, search and canvas all become available, and your account name appears at the bottom of the sidebar — read from your own session token in this browser.

Each person uses their own account. Credentials are never pooled, shared or redistributed. Which models you can reach, and what rate limits apply, are set by your own ChatGPT plan — not by CorX Labs.

That is the whole of it, in the client's own words. The auth module is @openai-oauth/web, bundled unmodified from the published package and served from this origin:

// assets/js/chat.js
import {
  completeLogin, getSession, logout, openaiAuthHeaders, startLogin
} from '/assets/vendor/openai-oauth-web.js';

await completeLogin();                 // finish a redirect we came back from
const session = await getSession();    // null → show Connect
// …and on every request to our own edge functions:
headers: { ...(await openaiAuthHeaders()), 'content-type': 'application/json' }

If something goes wrong, do not guess. Connection test in the profile menu prints the state of every link in the chain to the terminal: whether a session exists in this browser, whether the auth headers could be built, what /api/models answered, and — if the server says it received no credentials — whether it saw the Authorization and chatgpt-account-id headers at all. A failure that is a transport or deployment problem is reported as one, and does not sign you out.

3. Models

The picker is filled from the Codex model catalog for your own account — the same list the Codex CLI reads — so it shows what you can actually reach today rather than a list that goes stale.

The catalog is requested with a client version, which returns the raw list rather than the filtered one, so preview models appear alongside the listed ones and are labelled as such. Each entry carries its family and default reasoning level, which is what the second line under each name in the picker is showing.

Expect to see the gpt-5.x family and their -codex variants, plus the -mini models when your plan includes them. Switching models mid-conversation keeps the thread — start on a fast one and move to a heavier reasoning model when a question turns out harder than it looked.

Which of them actually run is set by your ChatGPT plan, not by CorX Labs. If one is refused, the error says which model was refused and what the upstream said; pick another from the same menu.

Image generation uses the catalog's image model through /images/generations on the same host.

5. The sandbox

The terminal is real. A full CPython build runs in WebAssembly inside your browser tab. The agent drives it: it writes code, runs it, reads the actual traceback when it fails, and fixes it. Every command and its output appear in the terminal panel as they happen — and you can type into it yourself.

It can install packages with micropip, create and edit files under /work, and reach the internet: inside Python, import web then await web.get(url). Those requests go out through /api/fetch on this origin, which is what stops CORS from boxing the sandbox in.

Because it runs in your tab, it has no access to your computer — only to its own in-memory filesystem and whatever you upload. Closing the tab discards it.

The shell understands pip install, ls, cat, rm, python <file>, pwd and help. Anything else is executed as Python — which is the honest framing, because that is what this is. There is no git, no node, no apt.

The panel closes with the × in its header, or the toggle in the chat toolbar. On a wide screen it reopens by itself when the agent next runs something. On a phone it does not — the panel is full-height there, and opening it over the answer you are reading would be rude — so the toolbar button gets a dot instead and you open it when you want it.

The point of showing it. An assistant that claims code works and one that shows you the passing output are different products. The terminal is there so you can check the second thing — and catch it doing something you did not intend.

6. Uploads, zips and downloads

Attach anything. Images go to the model as multimodal content, so it reads what is actually in the screenshot or photo. Every other file is written into the sandbox at /work/<name> — bytes intact — and the agent is told it is there.

Zips work, because Python's zipfile is in the standard library and the sandbox is real Python. Upload an archive and it can unpack it, edit what is inside, rebuild it, and hand the new file back: deliver_file pushes any sandbox file to you as a download, and everything the sandbox produces also appears in the canvas.

Files stay in your browser throughout. They are never uploaded to a CorX server.

7. Canvas

Canvas is a live file tree of the sandbox, not a rendering of the chat. Anything the agent writes appears there within a step of being written, with its extension and size. Click a file and it opens in an editor you can type in.

The editor is wired straight through to the sandbox filesystem. Save writes your edit back to /work, so the next thing the agent runs uses your version — you can correct a variable it got wrong and tell it to run the script again, without describing the fix in prose. Delete removes the file from the sandbox as well as from the tree. Download hands you the file as it currently stands.

Generated images land here too, as read-only entries you can download. The counter on the Canvas tab is how many files the sandbox is holding.

The conversation stays a conversation; the artefacts stay artefacts, and stay editable.

8. Agent mode and task planning

There is no agent mode to switch on. Give it a goal and it plans, then executes — writing files, running them, reading the traceback, searching, fixing, and handing you the result.

Planning is a tool, not a narration. For anything past two steps the model calls set_plan with the list of steps; the Plan panel fills in and the first step goes active. As it finishes each one it calls complete_step and the checklist ticks over. You are watching real state, not a paragraph that claims progress.

Every tool call also appears inline in the conversation as a card — what was called, the argument, and the output it actually returned, including failures. Nothing runs out of sight.

Plans are revisable. If the third step is wrong you can say so while the first two are still running, rather than waiting for a finished answer built on a bad assumption. Stop in the composer aborts the run mid-stream.

An interrupted run is not lost. If you close the tab or refresh while the agent is working, the next visit offers to pick it up where it stopped — and it is told to check what already exists in the sandbox before repeating work.

9. Reasoning and research

Answers that need more than a line open with the model's reasoning, collapsed into a thought process dropdown. It is asked to actually think in there — weigh an alternative, name the case that breaks its plan, say when it is unsure — rather than narrate. Open it when you want to know why; ignore it when you do not.

Search is real. web_search returns live results with titles, URLs and snippets, and each source appears in the answer as a chip carrying that site's own logo, linked so you can go and check it. fetch_url then opens any of them and reads the page itself, so a claim can be traced back rather than taken on trust.

That is the machinery deep research needs: search to find candidates, fetch to read them, and the sandbox to compare or compute across them. How thoroughly it is used on any given question is the model's judgement, and the sources stay attached so you can audit that judgement.

10. Language and region

CorX Chat detects the language you write in and answers in that language, including mid-conversation switches. It also detects your country or region so that locally-dependent answers and research are relevant where you actually are.

Both are defaults, not rules. Ask it to answer in English regardless, or to stop using your region, and it will for the rest of the conversation.

11. Conversations, memory and your profile

Chats are saved in the sidebar and restored when you come back, so closing the tab mid-task does not lose the thread. Up to 20 conversations are kept, each holding its last 60 messages; click one to switch to it, or the bin icon to delete it. New chat starts a fresh one without touching the others.

Memory is the switch in your profile menu, and it controls what gets sent. On — the default — the whole conversation goes with each message, so it can refer back to what you said earlier. Off, only the last exchange is sent and nothing new is written to storage.

Everything is stored locally, in localStorage under corx.chat.v2, not on a CorX server. Clearing your browser's site data removes both the conversations and the stored credentials.

The profile menu is also where your ChatGPT account name and email are shown — read from your own session token in this browser, never from a CorX record — along with the light / dark / system switch and Connection test, which prints to the terminal exactly which link in the auth chain is failing if something goes wrong. Sign out discards the credentials.

12. Privacy and credentials

The design rule is simple: CorX Labs never holds your ChatGPT credentials.

  • The extension performs the OAuth handoff; the website never sees the exchange.
  • Credentials are stored encrypted in your browser's own storage.
  • They are attached to individual requests from your side and used to call the proxy for that request only. They are not persisted server-side between requests.
  • There is no pooled or shared token. Every user's access is their own.

Anything you send — messages, attachments, files created in the sandbox — is processed to answer you, and your prompts go to your own ChatGPT account, so OpenAI's terms and data handling apply to that leg exactly as they would if you were using ChatGPT directly. Don't paste secrets you wouldn't paste into ChatGPT.

13. Limits

CorX Chat is an interface and an orchestrator built by a one-person lab. It is genuinely useful and it is not a hardened commercial product. Here is where it stops.

  • It depends on your ChatGPT plan. Model availability, quality and rate limits are your account's, not ours. If your plan can't reach a model, neither can this.
  • The request has to travel through this site's server. ChatGPT does not allow a browser to call the Codex backend directly, so messages go out from CorX Labs' server. That address is a datacentre, and ChatGPT's network edge sometimes turns datacentre traffic away before it reaches the API. When that happens you get a clear message saying so — it is not your account, your plan or your model, and there is nothing you can do about it from your side.
  • The extension is required. There is no way to use it without installing the sign-in extension, and it works only in browsers that extension supports.
  • The models still make mistakes. The terminal and the visible sources exist so you can check the work, not so you can skip checking it.
  • The sandbox is bounded. Sessions are isolated and not permanent; long-running or resource-heavy jobs can be cut short, and the sandbox has no access to your machine.
  • Deep research is a judgement, not a guarantee. Weighting sources by reliability is better than ignoring the question — it is not the same as being right.
  • Not for safety-critical use. Same rule as everything else CorX Labs publishes.

14. FAQ

Does CorX Labs see my credentials?

No. The extension performs the OAuth handoff and stores credentials encrypted in your browser. They are attached to individual requests from your side and are not persisted server-side. There is no pooled token.

Which models can I use?

Whichever your own ChatGPT plan can reach — typically the gpt-5.x family and their -codex and -mini variants. The picker is filled from the Codex model catalog for your account at runtime, so it reflects your plan rather than a fixed list, and each entry shows its family and default reasoning level.

Is the terminal real?

Yes — a full CPython build running in WebAssembly in your tab. The agent writes code, runs it, reads the real traceback when it fails and fixes it; it installs packages, reads and writes files (zips included), searches the web, generates images and reaches the internet. Every command is visible, and you can type into it yourself. It has no access to your computer.

Where does my chat history live?

In this browser, under corx.chat.v2 in localStorage — never on a CorX server. Up to 20 chats are kept, each holding its last 60 messages, and they come back in the sidebar when you return. Turning Memory off in your profile menu stops new messages being saved; deleting a chat removes it; clearing site data removes everything along with your stored credentials.

It says the request was blocked before reaching ChatGPT. What now?

That is ChatGPT’s network edge refusing the address the request came from — this site’s server — before the API ever saw it. It is not about your account, your plan or the model you picked, and switching models will not help. Run Connection test from your profile menu: if it reports the block, the fix is ours to make, not yours. Trying again later sometimes works, since the block is not always permanent.

Can I plug in my own backend?

Yes. The interface never talks to a model directly — every turn goes through CorxChat.transport.send, which posts to CorxChat.config.endpoint. Replace that one function and the whole UI runs against your own orchestrator.
